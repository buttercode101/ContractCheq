# ContractCheq reality audit — 22 October 2026

Scope: ContractCheq only. Baseline main `bb916330522f6fcb3bd7886af76b86db80f41056`, production `contractcheck.online`. Findings come from executable code and reproduced behavior, not historical phase documents. This audit cannot establish failure-free software or legal completeness.

## Running reality

`public/index.html` is a React UMD application, with `public/app.css`, `public/contract-actions.js` and `public/checklist-tools.js`. It calls an Express application in `server/index.js`; root `index.js` is a compatibility entry. `build-vercel.js` packages the Node 24 function and browser assets; `vercel.json` selects Cape Town and daily cleanup.

Upload -> PDF text extraction or English OCR -> `server/riskEngine.js` -> rule findings, plain-language sections, context and action plan -> optional explicit-consent OpenRouter -> private `server/store.js` report -> allowlisted free preview. PDF OCR accepts up to three scanned pages; documents are capped at 200,000 characters and production uploads at 4 MB. More complex documents need splitting. Rule coverage is finite. UK tenancy checks explicitly cover England, not every UK legal system.

Paystack callback -> server verifies amount, currency, product and receipt email -> idempotent grant -> optimistic-concurrency credit spend -> full report. Local browser state cannot grant server access. Receipts can recover unused credits and retained reports. Uploaded originals are deleted after processing. Reports expire after 48 hours and are removed by access or daily cleanup. Receipt/limited telemetry records currently have no scheduled expiry; the privacy page says so.

Full reports expose original wording beside the reading guide, source-backed payment/obligation summaries, manual confirmed dates, PDF export and device-only checklist backups. Calendar export does not compute conditional deadlines or send reminders. This remains contract triage, not a contract drafting/signing service or legal clearance.

## Reproduced high-priority defects and fixes in this change

| Issue | Observed evidence | Exact change |
|---|---|---|
| Unrelated negation hid risky terms | In `server/riskEngine.js`, “Tenant must not delay rent payments and landlord may enter the dwelling without notice” omitted the entry flag; an assignment prohibition also hid a subsequent non-refundable deposit. | Scope negation/prohibition to the conjunction-separated clause, retain genuinely protective clauses, add regression cases in `server/riskEngine.test.js`; increment ZA/UK rule versions. This remains a heuristic, not a complete grammar parser. |
| Individual AI origin was missing | `public/index.html` rendered an AI badge only for `source === groq`; OpenRouter is the production provider. `server/index.js` dropped source from locked previews. PDFs omitted origin. | Label both providers, preserve source in locked previews, print AI origin in PDF; verify rendered markup/export and the actual browser AI journey. |
| Late credit response could overwrite later navigation | Ordinary `unlock` lacked the request identity/abort checks already used for uploads and reopening. | Use the existing report-request controller, ignore stale responses, propagate cancellation; test the shipped handlers in `server/uiJourney.test.js`. Server-authorized spends remain recoverable. |
| Late payment callback could replace a different report | Callback closed over the old report and unconditionally called `setResult(full)` after its requests. | Check active view/report before displaying completion, preserve paid-report recovery and inform the user when completion happens elsewhere. Verify real application handlers and delayed browser responses. |
| Receipt/payment requests could stay pending indefinitely | Restore, callback verification and ordinary unlock used unbounded browser fetches. | Add a 25-second JSON request deadline covering response-body reading; preserve receipt/reference and offer retry without paying again. Verify timeout and retry controls with injected network stalls. |

## Medium/low findings and alignment

| Item | Evidence / action |
|---|---|
| Browser coverage omitted Chromium | `.github/workflows/browser-verification.yml` previously covered Firefox/WebKit only. Add Chromium alongside both, retaining viewport/accessibility/error/receipt/upload/export checks. Automated desktop engines do not substitute for a physical low-end Android device. |
| Duplicate samples | Three root `samples/*.txt` were byte-identical to active downloads in `public/samples/`; code references `/samples/` served from `public`. Delete the unused root copies; retain downloadable fixtures. |
| Unused dependency | No application import/reference to `cors`; no cross-origin service contract. Remove direct `cors` dependency and unused transitive dependency through npm, preserving the lockfile. |
| Large deployment bundle | `build-vercel.js` copies all production `node_modules` into the function, including OCR/PDF native assets. A targeted bundling change should be a separate measured refactor with cold-start, image-format and multipage extraction regressions. Do not delete runtime assets based only on size. |
| Maintainability | `server/index.js` and the inline application combine several concerns. Extract payment/network/report modules incrementally after these behavior regressions are protected; avoid a framework rewrite in a corrective release. |
| Legal/extraction limits | Regex rules can still miss unfamiliar language; English OCR may misread poor scans; date/action extraction is bounded. Retain coverage warnings and source wording; expand a representative corpus before claiming broader coverage. |
| Payment verification boundary | Automated provider responses are isolated synthetic fixtures. Real Paystack SDK availability can be tested without charging. Actual customer payment/settlement, chargebacks, refunds and bank payout need a separately recorded real transaction; this audit does not claim those passed. |

## Verification and evidence

Local baseline: 97 tests passed. After the corrective changes: 103 tests passed, smoke test passed, production dependency audit found zero vulnerabilities, production packaging and diff hygiene passed. Tests include actual Express requests, PDF/OCR fixtures, credit replay/concurrency, free-field gating, input validation, retention, AI consent/failure and execution of shipped frontend handlers.

Browser suite: `scripts/verify-recovery-browser.cjs` plus edge/AI modules exercises upload, simulated provider verification/unlock, fresh-session recovery, PDF download, roles, local checklists, backups/import/delete, calendar confirmation, quota/missing assets, errors, mobile landscape and navigation, AI consent/success/failure, and real SDK loading. Browser matrix checks widths 320 through 1920 and WCAG A/AA violations. CI artifacts retain screenshots and structured assertions for seven days. Final run/deployment identifiers and live outcomes belong in the release PR, rather than being assumed before CI completes.

## Prioritized remaining work / suggested PRs

1. **Fix clause detection, AI attribution and payment recovery races** — this change; ship only after automated and browser gates pass, then recheck deployed bytes/security headers and synthetic production uploads.
2. **Measure and reduce OCR function packaging** — retain native PDF/canvas/Tesseract assets while reducing unused packaged code; compare function size, cold starts and every supported extraction format.
3. **Split payment and report controllers behind existing journeys** — remove duplicated request handling and make navigation/state transitions easier to review without changing the product.
4. **Extend the contract corpus and physical Android verification** — add approved real-world anonymized inputs, conditional/negated wording and low-quality scans, and record physical-device evidence. Do not infer legal correctness from test count.
5. **Record an authorized real Paystack settlement** — verify charge, server grant, receipt recovery, export, merchant transaction and settlement; record exact evidence without exposing payment details. No real-money transaction is created by this release.

Quick wins implemented: scoped clause checks, AI badges/export attribution, bounded receipt requests, stale-response protection, Chromium CI and duplicate/dependency cleanup.
