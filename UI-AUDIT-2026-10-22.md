Baseline: `2c16714e9f185c44609208c1389433105d6499e7` on `main`.

The initial browser usage restriction cleared after its stated reset time. This pass then inspected the live home, pricing, checkout dialog, Privacy, Terms, Contact, saved-checklist empty state, report overview and reading guide in Chrome at 1363 × 936. Current source and executable regression checks supplement these observations; earlier markdown claims are not the baseline.

## Findings and changes

| Finding | Actual evidence and source | Change |
| --- | --- | --- |
| Misleading initial AI availability | Live page first called AI unavailable, then enabled it after configuration arrived. `public/index.html`, configuration effect and `.ai-option`. | Distinguish checking, connection failure and confirmed unavailability; keep AI disabled until settings load. Clear selection on reconnect. |
| No deadline or retry for service configuration | Source used a direct fetch without abort or recovery. Pricing actions depend on this request. `public/index.html`, mount effect. | Use the existing 25-second JSON helper; validate all prices; provide a shared retry panel with busy feedback and stale-response protection. |
| Disabled checkout without loading explanation | `public/index.html`, payment caption. | Announce checkout availability checking. |
| Purchase actions below the initial desktop screen | Live pricing showed ten feature rows in the single-report card, stretching every card and placing all purchase actions below the 936-pixel viewport. `public/index.html`, `plans`. | Use four concise benefits in the card; preserve the complete feature list in a shared expandable section. |
| Dense legal pages | Live Privacy and Terms used uninterrupted paragraph groups without topic headings. `public/index.html`, legal views. | Add descriptive section headings; retain substantive wording. |
| Support address could not open email | Live Contact rendered the address as plain text and repeated the payment-reference instruction. `public/index.html`, contact view. | Add a mailto link and remove duplicated instructions. No message is sent automatically. |
| Same browser title on every route | Live navigation retained the landing title. `public/index.html`, view effect. | Add descriptive titles without uploaded filenames. |
| Small dismiss controls | CSS defined error/notice buttons at 32 × 32. `public/app.css`. | Increase to 44 × 44; use existing design tokens for recovery and disclosures. |

## Confirmed baseline behaviour

- Home fonts loaded; no horizontal overflow at the observed desktop size. Hero text was upright.
- Checkout opened with email focus, a clear price and reachable close control; closing restored focus to Buy R19. No purchase was submitted.
- Navigation's active state followed the selected page.
- Example report overview, findings and reading guide loaded. Reading-guide navigation placed the section at y=112 below the sticky header at y=79.
- Searching for “deposit” reduced the example guide to two matching sections.
- Saved-checklist empty state explained local storage and exposed backup restoration.
- Browser logs contained extension-origin metadata errors; these are not attributed to the application.
